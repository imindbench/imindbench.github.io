Submit a model

A submission is a pull request that adds one model's public metadata and its generated publication artifact. Raw evaluation outputs stay outside the repository; the tooling reads them from a path you pass in.

Open a submission pull request View the pull request template

The repository is currently private, so the links above require access. Everything the template asks for is listed below.

1. Write the submission file

Keep your complete population_*.json results in a directory outside the repository, named with a stable model ID: a lowercase underscore-separated slug. Use the same ID in leaderboard/data/submissions/<model_id>.json: 

{
  "schema_version": 1,
  "model_id": "example_model",
  "display_name": "Example Model",
  "pretrained": true,
  "pretrained_on": "Public Dataset",
  "description": "Short public description of the evaluated model.",
  "coverage_note": null
}

pretrained_on must be null when pretrained is false, and coverage_note is either null or a non-empty string. Unknown fields, and an ID that disagrees with the raw results, are rejected.

2. Add the model and validate

From leaderboard/, read the dry run before it writes:

python add_model.py \
  --model-outputs /path/to/evaluation_outputs/example_model \
  --submission data/submissions/example_model.json \
  --dry-run

python add_model.py \
  --model-outputs /path/to/evaluation_outputs/example_model \
  --submission data/submissions/example_model.json

python validate_data.py

The dry run reports runs, logical entries, fold records, and a coverage: observed/expected (status) line per preprocessing entry. Applying it writes data/models/<model_id>.json and adds it to data/manifest.json. There is no CI check yet, so the validator has to pass locally.

3. Commit and open the pull request

Commit exactly three files:

  • leaderboard/data/submissions/<model_id>.json
  • leaderboard/data/models/<model_id>.json
  • leaderboard/data/manifest.json

No raw outputs, caches, or private contact metadata, and no unrelated model artifact in the diff. The template asks for the submission file, the coverage line from the dry run, and the model's provenance.

Partial coverage

Missing benchmark cells make coverage partial rather than failing the submission. The leaderboard flags a partial model with an automatic footnote counting the missing result cells and appends your coverage_note to it, so the note can explain the gap but cannot replace or suppress that text. On a complete model it is dropped and never displayed.
